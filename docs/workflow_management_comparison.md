# 워크플로우 관리 방식 비교

## 1. Python 코드 기반 (현재 방식)

### 장점 ✅

1. **타입 안정성**
   - IDE 자동완성 지원
   - 타입 체크 가능
   - 컴파일 타임 오류 발견

2. **로직과 메타데이터 통합**
   - 워크플로우 코드와 메타데이터가 같은 곳에 있어 이해하기 쉬움
   - 코드 리뷰 시 전체 맥락 파악 가능

3. **리팩토링 용이**
   - IDE의 리팩토링 도구 활용 가능
   - 함수명 변경 시 자동 업데이트

4. **버전 관리**
   - Git으로 코드와 메타데이터 함께 관리
   - 변경 이력 추적 용이

5. **런타임 오류 최소화**
   - Python 코드 검증이 먼저 이루어짐
   - YAML 파싱 오류 없음

### 단점 ❌

1. **메타데이터 수정 시 재시작 필요**
   - enabled, priority 등 변경 시 서버 재시작 필요

2. **비개발자 접근 어려움**
   - 메타데이터 수정이 코드 수정 필요

3. **동적 변경 어려움**
   - 런타임에 워크플로우 활성화/비활성화 어려움

---

## 2. YAML 기반 방식

### 장점 ✅

1. **런타임 동적 변경**
   - 서버 재시작 없이 메타데이터 수정 가능
   - 설정 변경 즉시 반영

2. **비개발자 친화적**
   - YAML 파일만 수정하면 됨
   - 코드 수정 불필요

3. **설정과 로직 분리**
   - 메타데이터 관리가 명확
   - 설정 파일만 백업/복원 가능

4. **대량 관리 용이**
   - 60개 이상의 워크플로우 메타데이터를 한 파일에서 관리 가능

5. **환경별 설정**
   - 개발/스테이징/프로덕션 환경별 다른 설정 가능

### 단점 ❌

1. **타입 안정성 부족**
   - YAML 스키마 검증 필요
   - 타입 오류는 런타임에만 발견

2. **코드와 분리**
   - 메타데이터와 로직이 분리되어 파악이 어려울 수 있음
   - 파일 간 이동 필요

3. **IDE 지원 제한**
   - 자동완성, 타입 체크 등 제한적

4. **YAML 파싱 오류**
   - YAML 문법 오류 가능성
   - 들여쓰기 등 문법에 민감

5. **버전 관리 복잡**
   - 코드와 YAML 파일을 따로 관리

## 3. 하이브리드 방식 (추천 ⭐)

**Python 코드에 기본값을 두고, YAML로 오버라이드하는 방식**

### 구조

```
agents/workflows/
├── business_trip.py      # 워크플로우 로직 (Python)
├── workflows.yaml        # 메타데이터 설정 (YAML, 선택적)
└── registry.py           # 하이브리드 로더
```

### 장점 ✅

1. **유연성**
   - 기본값은 코드에 (개발자용)
   - 오버라이드는 YAML로 (운영자용)

2. **안정성**
   - YAML이 없어도 기본값으로 동작
   - 타입 안정성 유지

3. **실용성**
   - 자주 바뀌는 것(enabled, priority)은 YAML로
   - 로직 관련은 Python 코드로

4. **점진적 마이그레이션**
   - 기존 코드 기반 방식에서 YAML로 점진적 전환 가능

## 추천 방안

### 60개 이상 워크플로우 관리 시

**하이브리드 방식 추천** ⭐⭐⭐⭐⭐

1. **워크플로우 로직**: Python 코드로 작성
2. **메타데이터**: YAML 파일로 관리 (priority, enabled, examples 등)
3. **자동 감지**: Python 코드의 `@workflow` 데코레이터를 기본값으로 사용
4. **YAML 오버라이드**: YAML이 있으면 우선 적용

### 사용 시나리오

- **개발 단계**: Python 코드에서 데코레이터로 등록
- **운영 단계**: YAML 파일로 메타데이터 관리 및 동적 변경
- **대량 관리**: YAML 파일 하나로 60개 워크플로우 메타데이터 관리
